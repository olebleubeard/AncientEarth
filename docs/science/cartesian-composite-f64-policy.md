# Prospective composite f64 solver evaluation

This is a separate engineering allocation following the rejected ten-route
experiment. The [coverage assessment](cartesian-f64-coverage-assessment.md)
and [independent publication assessment](../../artifacts/optical-cartesian-f64-selected-first-publication-assessment.json)
distinguish its required-route failure from the exact original-eye fallback
and the nine published suffix results that passed their frozen metrics. That
experiment remains rejected. The earlier component cost/context rejections
also remain unchanged. None is relabeled as a pass.

The question here is whether the same unchanged f64 suffix, used as a partial
accelerator with exact original-eye fallback, can preserve final results and
materially reduce total work. The complete promoted numeric shader must remain
byte-identical to the reviewed selected f64 module. No tolerance, coefficient,
admission, source-root, scene, field or iteration policy changes are permitted.
The existing prefix and fallback retain their original numerical expressions.
Only reviewed case packets, launch/stub conventions and metadata may vary.

The starting selected sample is the already retained first f64 run; do not
rerun it. Its previous ten-route verdict stays rejected, while its raw outputs
can supply the separately labeled composite final-output checks. All physical
handoffs, launches and prefix counts must match the frozen controls. Final
route is reported separately from physical identity. Every unhanded, masked or
fallback record must match all twelve original terminal words. Every published
suffix must preserve original sky classification and satisfy all three frozen
same-ray error ceilings. A fallback is not a promoted-solver accuracy pass.
Preexisting selected-original errors, including the recorded fallback endpoint
error above 5 m, remain explicit under the previously frozen selected scope;
the separate atmosphere limits are not changed or reassigned.

The first new candidate packet is `atmosphere-100-gradient`. Its original
baseline, canonical references and exact rational ceilings are already frozen.
Its final outputs retain the strict endpoint/path/direction limits
`<5 m`, `<5 m`, `<3e-6`, as do the other atmosphere controls. Each accepted
suffix additionally satisfies the same original-ray error plus measured
reference-convergence allowance. Unhanded/fallback outputs must be exact
original, including every terminal class, normal and owner field. Any invalid,
missing or newly unresolved output relative to its original class, altered
original terminal, failed numerical
gate or changed source stops this candidate without tuning.

The remaining named cases are `readiness`, `fisheye`, `vacuum-outward`,
`vacuum-inward`, the other five existing height/profile atmosphere presets,
and `returning-gradient`. Reuse the ten retained original branch/atmosphere
baselines and their existing conventions. Readiness retains its no-attempt
original unresolved result; fisheye must exercise masked and unmasked records;
vacuum preserves the exact original outward sky or inward uncovered-h0 result.
The atmosphere cases retain their explicit no-contact/covered-h0 diagnostic
stubs and are not terrain/contact tests. These are eighteen unique atmosphere
launches repeated in the 23-record packet interface, not 138 independent cases.

`returning-gradient` keeps the actual empty-scene visibility code and the
retained physical input, without the atmosphere-only stubs or an artificial
fixed-path stop. Before its candidate run, freeze a fresh original full-trace
baseline and an independently converged reference using that baseline's
actual launch. The reference must demonstrate the outward-to-inward turn and
first downward uncovered-h0 event. The candidate must actually hand off to the
suffix, then take original-eye fallback and return the exact original surface
terminal; an unhanded original result alone does not close this execution gate.
This control is a refractive returning-ray test, not a claim of meteorological
temperature-inversion provenance.

All routes, reasons, prefix/suffix/fallback counts and discarded work are
retained. At least one genuine suffix completion and the described returning
fallback must be demonstrated. Coverage counts are otherwise descriptive;
the old exact set of ten accelerated records is not a new final-accuracy gate.
There are no f32 accepted-step logs in this f64 ABI: source/assembly proofs,
valid state/progress/terminal records and the unchanged final reference gates
are required, without claiming internal f32 step identity.

The distinct host mode is selected and untimed. Its reference option applies
only to the new returning baseline and removes only the optional prefix
handoff. Each new candidate's source, five uploads and baseline association
must be independently checked. Finish the complete correctness matrix before
enabling any full-frame timing. An eventual matched complete-chain run must
meet the unchanged rule: at least 20% median reduction and the prescribed
separated retained sample ranges, including initialization, prefix, suffix,
discarded work, original fallback and validation. All-fallback output cannot
pass merely through byte parity. No isolated suffix cost or subset of passing
cases establishes native moving-view performance or production acceptance.
