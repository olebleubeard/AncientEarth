# Bounded f64 Cartesian suffix feasibility

This is a separately authorized engineering effort after the two precision
component workloads were rejected. The checksum workload remains unqualified
for timing; the fully observed workload passed its arithmetic checks but
failed its fixed cost-range rule. Neither verdict or threshold changes. The
engineering decision permits a bounded controller feasibility implementation
because the continuous uploaded-field handoff screen and actual timed trial
arithmetic passed their numerical gates. It supplies no controller speed
prediction or production approval.

## Initial cases and fixed acceptance

The initial host accepts only two selected, untimed cases:

- `selected`: the existing 23 actual rays, requiring the same ten completed
  suffix routes and thirteen exact original-route terminal records. Saved
  handoff position, direction, path, entry, geometry, owner, launch and prefix
  attempt count remain bit-exact. All thirty frozen same-ray metrics apply.
- `atmosphere-100-gradient`: the existing 23-record packet containing three
  repeated launch directions. All 23 suffix routes and every frozen same-ray
  and absolute atmosphere limit must pass. The existing uploaded packet and
  diagnostic no-contact/covered-h0 conventions are retained exactly.

These are 46 output records, with 33 required suffix completions and thirteen
original terminals. The eleven preceding CPU/trial handoffs covered the ten
actual rays and only record 1 of the atmosphere case. They are supporting
evidence, not proof for the other atmosphere directions. No new original
baseline, metric allowance or tolerance factor is selected from candidate
outputs. A fallback cannot conceal a failed required suffix route. Any failed
numerical or identity gate stops this candidate without retuning.

Only after these cases pass may the existing branch/atmosphere matrix be
completed, including a prospectively frozen returning/turning reference. Full
packet and timing modes remain disabled until those gates close. One eventual
matched complete-chain timing must include prefix, suffix, discarded work,
original fallback, initialization and validation, and pass the unchanged 20%
effort gate. Native moving-view acceptance remains separate.

## Arithmetic and ownership

The exact legacy prefix and original-eye fallback modules remain unchanged.
The suffix starts by widening the saved f32 position, raw direction, path and
entry exactly. It does not normalize the initial direction. Uploaded matrix
rows, origin and source layers widen exactly; there is no symmetrization,
canonical ellipsoid reconstruction or slope recalculation. Geometry is
recomputed in f64 and must be strictly inside the saved owner's uploaded
bounds, including the below-base branch. Invalid, nonfinite, out-of-domain or
uncertain ownership restarts the original-eye fallback.

Promote the complete Cartesian core with the reviewed deterministic token/type
method: stage positions/directions, field evaluation, RK and dense coefficients,
normalization, embedded/interior estimates, source-root brackets and charges,
step proposals, state commits and path accumulation. Rational expressions and
the fixed `0.25 * max(0.002, 4e-7 * length(state.p))` controller are retained.
Per-accepted-step normalization remains. No state, length, coefficient or root
is rounded back to f32 inside the integration. Final terminal fields convert
once to the existing output ABI. Prefix attempts count against the unchanged
4096 limit; suffix failure discards its work and reruns the exact original eye.

Source and h0 guards remain mandatory. Only a successful sky exit can publish
a suffix result. A possible scene/h0 event or failed clearance proof invokes
the original solver; this effort does not port a contact algorithm.

## Scene exclusion bridge

Every accepted prefix of the original full dense trial must be certified
scene-free before commit or terminal publication. The existing sufficient-only
f32 interval/Bernstein exclusion can consume outward f32 intervals enclosing
each actual stored f64 position and coefficient, accepted distance, full trial
distance and supplied error components. A rounded representative passed to
`cs_exact3` is insufficient.

The bridge verifies its converted endpoints enclose the actual f64 operand;
overflow, nonfinite values or failed containment reject. Tiny values receive
normal outward bounds that survive flush-to-zero. The clipped parameter ratio
is formed outward from distance intervals, including the division allowance.
All original terrain/marker root validation, source/frame padding, transformed
error-tube gain, derivative speed gain and broadphase sag allowances remain.
The unchanged larger f32 dense-evaluation rounding band may be retained only
after its applicability to the promoted polynomial is independently checked.
The sum of the supplied integration error and source allocation is enclosed
outward and must fit the unchanged f64 tolerance; this bridge adds no budget.
Nonseparation fails before any suffix state or terminal is published.

## Interface and review

The new math-owned constructor is
`optical_cartesian_suffix_f64_fixture::build(case: &str) -> SuffixFixture`.
It retains the existing 24-word saved-handoff state, 12-word terminal,
8-word detail and 16-byte progress interfaces. Internal f64 arithmetic needs
no new persistent numerical buffer. The diagnostic device explicitly requests
f64 and int64 support; unsupported devices do not execute this candidate.
New source, assembled closure, conversion/clearance proof, input identity and
host dispatch reviews precede GPU execution. The old rejected fixtures and
their raw evidence remain immutable.
