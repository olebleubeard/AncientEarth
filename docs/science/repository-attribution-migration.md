# Repository attribution and retained scientific evidence

The repository attribution was migrated to [olebleubeard/AncientEarth](https://github.com/olebleubeard/AncientEarth), displayed as **oleBlueBeard**, on 2026-11-01. The archive transformation did not rerun numerical tests or benchmarks and does not change any recorded scientific result or acceptance decision. Any application rebuild for the migration is separate from those historical experiments.

Attribution-only copies were prepared and verified for ten assistant-created source archives. Their archived `Cargo.toml` repository URL changed; nested copies of affected archives and the corresponding `paths.json` content addresses, sizes and hashes changed with it. Every other leaf payload, including solver sources, shader sources, numerical inputs, outputs, reference values, policies and historical run manifests, remains byte-identical. Manual backups were not included in this operation.

Historical run manifests and original archive reports retain their original fingerprints. Those fingerprints describe the bytes available during the recorded run; they are not claimed to be the current hashes of sanitized archive containers. The [archive migration mapping](../development/archive-attribution-migration.json) records original and sanitized container/member hashes and the exact allowed changes. It certifies preparation of the copies, not their later installation: compare an installed archive's hash with `sanitized_sha256` to verify which version is present. Use the mapping and each sanitized archive's `paths.json` to verify the attribution-migrated contents. An unchanged historical hash check against an affected sanitized container or `Cargo.toml` will intentionally differ; this is documented provenance migration, not evidence that the experiment was rerun under the new identity.

Separately, the [performance metadata mapping](../development/performance-identifier-migration.json) covers machine-name prefix sanitization in `discoveredCounterPaths` of three ignored performance JSON records. Counter measurements, process/engine identifiers and all other bytes remain unchanged. The replacement is an identity label, not a claim that measurements were recollected or that the machine had the replacement name during the recorded runs.
